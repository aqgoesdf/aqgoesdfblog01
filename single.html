Entendendo closures em JavaScript na prática

AG AqGoEs · 12 de julho de 2026 · 6 min de leitura

Closures são um dos conceitos que mais geram confusão em quem está começando com JavaScript — e, ao mesmo tempo, um dos que mais aparecem no dia a dia sem que a gente perceba. Neste artigo, quero desmontar o conceito com exemplos simples, do jeito que gostaria de ter aprendido quando comecei a migrar da área técnica para o desenvolvimento web.

O que é uma closure, na prática

Uma closure acontece quando uma função "lembra" do ambiente em que foi criada, mesmo depois que esse ambiente já deveria ter deixado de existir. Isso é possível porque o JavaScript usa escopo léxico: uma função sempre tem acesso às variáveis do escopo onde foi definida.

contador.jsJavaScript
function criarContador() {
  let total = 0;

  return function() {
    total++;
    console.log(`Total: ${total}`);
  };
}

const contador = criarContador();
contador(); // Total: 1
contador(); // Total: 2

Repare que a variável total não é global e não é recriada a cada chamada — ela vive dentro da closure retornada por criarContador. Isso é exatamente o que permite manter um estado privado sem recorrer a variáveis globais.

Onde isso aparece no dia a dia

  • Em funções de callback que precisam lembrar de um valor específico.
  • Em event listeners que carregam contexto de quando foram criados.
  • Em padrões de módulo, antes da chegada do ES Modules.
Entender closures não é decorar a definição — é reconhecer o padrão quando ele aparece disfarçado de função dentro de função.

Um erro comum: closures dentro de loops

Um erro clássico é criar closures dentro de um loop usando var, esperando que cada função "lembre" do valor da iteração em que foi criada. Como var não tem escopo de bloco, todas as funções acabam compartilhando a mesma variável.

  1. Troque var por let para obter escopo de bloco.
  2. Ou envolva a lógica em uma função separada que receba o valor como parâmetro.

Depois de anos resolvendo problemas de rede e suporte técnico, achei curioso perceber que closures resolvem, no fundo, o mesmo tipo de problema que eu via em sistemas distribuídos: manter estado isolado e previsível. A lógica muda de contexto, mas o raciocínio se repete.
